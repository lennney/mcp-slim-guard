# Support

Use the GitHub issue templates for public support:

- **Bug report:** reproducible Slim Guard behavior.
- **Compatibility report:** one MCP Host and upstream Server combination.
- **Feature request:** a user problem or missing workflow.

Before opening an issue:

1. Check the current README and existing issues.
2. Record the Slim Guard, Node.js, Host, and upstream Server versions.
3. Reduce the report to one behavior.
4. Remove credentials, private paths, Tool arguments, result bodies, and raw
   Tool or result references.

Do not use a public support issue for a vulnerability or code-of-conduct
report. Follow [SECURITY.md](SECURITY.md) or
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
